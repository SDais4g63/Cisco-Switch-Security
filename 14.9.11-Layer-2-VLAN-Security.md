# Lab 14.9.11 — Layer 2 VLAN Security

## Project summary

Cisco Packet Tracer lab documenting a redundant 802.1Q switch trunk, a dedicated management VLAN (VLAN 20), router-on-a-stick management routing, and ACL/SSH restrictions. This is a student lab based on Cisco Networking Academy; the notes and screenshots document my observed configuration and testing.

**Tools:** Cisco Packet Tracer, Cisco IOS CLI, VLANs, 802.1Q trunks, STP, extended ACLs, SSH.

## Network design

![Packet Tracer topology](../screenshots/14.9.11/01-network-topology.png)

The topology includes R1, Central, SW-1, SW-2, SW-A, SW-B, management workstation C1, and client hosts in VLANs 5 and 10. SW-1 and SW-2 have an additional redundant FastEthernet0/23 connection.

## Secure switch trunk and STP

- **SW-1 Fa0/23:** administrative and operational trunk modes, 802.1Q, native VLAN 15, DTP negotiation off.
- **SW-2 Fa0/23:** same trunk settings.
- VLAN 20 is allowed and active on the trunk. The SW-2 `show interfaces trunk` output lists Fa0/23 as not forwarding under STP, consistent with loop prevention on a redundant topology.

## Management VLAN 20

On SW-A, `show vlan brief` shows VLAN 20 active with management PC port Fa0/1 assigned; `show ip interface brief` shows `Vlan20` at `192.168.20.1` and up/up. Other management IPs defined in the assignment include SW-B `.2`, SW-1 `.3`, SW-2 `.4`, Central `.5`, and router R1 `.100` on the `192.168.20.0/24` subnet. ## Router-on-a-stick and access controls

R1's GigabitEthernet0/0.3 is up/up and configured with `encapsulation dot1Q 20`, IP `192.168.20.100/24`. ACL 101 is configured to deny traffic destined for `192.168.20.0/24` and then permit other IP traffic, applied inbound on VLAN 5 and VLAN 10 subinterfaces. ACL 102 permits host `192.168.20.50` and is applied to VTY lines for restricted SSH administration (`access-class 102 in`, `transport input ssh`, `login local`).

The ACL output also displayed 10 matches on ACL 101's deny entry; match counters alone do not identify individual flows.

## Observed testing

| Test | Observed result | Interpretation |
|---|---|---|
| C1 → SW-A (`192.168.20.1`) | 3 replies, 25% initial packet loss | Reachable |
| C1 → SW-B (`192.168.20.2`) | 3 replies, 25% initial packet loss | Reachable |
| C1 → R1 (`192.168.20.100`) | 4 replies, 0% packet loss | Reachable |
| D1 (VLAN 5) → C1 (`192.168.20.50`) | 0 replies, 100% packet loss; destination unreachable | Consistent with intended management VLAN restriction |
| C1 → R1 SSH (`ssh -l SSHadmin 192.168.20.100`) | Authenticated session reached `R1#` | Authorized management access works |

Initial ping loss may occur during ARP resolution; it does not imply that the ACL denied those requests.

## What I learned

- How to inspect trunk operational mode, native VLAN selection, and DTP status.
- How spanning tree can block a redundant link while preserving loop-free forwarding.
- How VLAN 20 separates management traffic from user VLANs.
- How to restrict router management using interface ACLs and VTY SSH access lists.
- How to distinguish expected blocked traffic from ordinary network failures during testing.
